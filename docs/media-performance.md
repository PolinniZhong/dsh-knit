# 媒体档性能：首屏分批 + 缩略图降采样（v0.28，2026-11-20）

## 1. 用户报的问题

> 「当媒体中数据多了以后加载比较卡」

## 2. 实测：卡在哪

隔离实例（`dsh plugin add link:` 装当前工作树），夹具 **60 张 2400×1600 / 1.3 MB JPEG + 3 个 mp4**，
同一个 Chrome（headless=new，1440×900），同一台机器。

把 N 张图按 104px 格宽挂进网格，等 `img.decode()` 全部完成：

| 同屏 N | 解出的位图常驻 | 全部 decode 完成 |
|---:|---:|---:|
| 12 | 176 MB | 232 ms |
| 24 | 352 MB | 269 ms |
| 40 | **586 MB** | 336 ms |

**根因不是「元素多」，而是「拿原图当缩略图」**：一张 2400×1600 解码后就是
`2400 × 1600 × 4 B = 15.4 MB` 位图，40 张 = 586 MB。列表每 5 秒轮询一次、切换档位、
滚动都在这堆位图上做，当然卡。

另外两条放大器：

- 视频缩略图是 `<video preload="metadata">`，**每张一条 Range 请求**；一屏 40 个播放器会把媒体管线压满。
- 客户端 `limit=40`，所以「同屏 40 张」就是常态上限；再多也只是 `total` 数字变大、列表并不增长。

## 3. 方案：两层，缺一不可

### ① 首屏分批（治并发）

- `mediaFirstBatch(columns)`：按当前列数估三行，夹在 **12–48** 张之间；
- 滚到底部的哨兵（`.knit-media-more`）进视口 ⇒ `mediaNextCount` 追加 **24** 张；
- **`mediaDocs` 本身不截断**（lightbox 的左右切换要全量），只截「上屏的那一份」；
- 键盘导航 / `aria-activedescendant` 跟着**挂载的那一份**走（看见什么就能走到什么）。

### ② 缩略图降采样（治位图内存）

- `useThumb(src, edge)`：`fetch` 同源原图字节 → `createImageBitmap(blob, { resizeWidth: edge })`
  **解码时直接缩到格宽 ×2**（96–320px）→ 画进 canvas → 输出 JPEG blob；
- 解码**限并发 2**（`THUMB_CONCURRENCY`），避免峰值叠起来；
- 小图进有上限的 LRU（`THUMB_CACHE_MAX = 240`，约 5 MB），换档 / 滚回来不重解码；
- 生成失败或老内核没有 `createImageBitmap` ⇒ **回落原图**，不白屏；
- 「看大图」（悬停放大、全屏查看器）仍然读原图，画质不受影响。

### ③ 视频看得见才挂

`useNearViewport` + `rootMargin: 240px`：卡片进视口附近才建 `<video>`，不再一屏 40 个。

## 4. 效果（同一套夹具、同一台机）

| | 改前 | 改后 |
|---|---:|---:|
| 首屏挂载 | 40 张（`limit` 上限） | 12–48 张（按列数，默认 15–30） |
| 40 张的解码位图 | **586 MB** | **4 MB**（40 × 208px 小图） |
| 缩略图管线耗时 | — | 12 张 299 ms / 24 张 433 ms / 40 张 673 ms（2 并发，后台可继续） |
| 视频元素 | 一屏全建 | 视口附近才建 |

> 缩小 **约 146×** 的常驻位图，这是「卡」的直接来源。
> ⚠️ 首屏之外的点：滚动追加是有代价的（每次多解码一批），但**一次只有一批**，
> 而且小图命中缓存后不再付第二次。

## 5. 边界与不做

- **没有加缩略图路由**：宿主侧零改动，仍然只读 `/knit/api/raw`；降采样在浏览器里做。
  （加服务端缩略图需要图片解码库 —— 本插件零依赖，不做。）
- 不做虚拟滚动 / 不等高瀑布流：网格仍是 CSS `auto-fill`，只是**上屏量**受控。
- 不改 `limit=40`：它决定「一次拿多少条元数据」，与「一次挂多少张」是两件事；
  真要更多条目，那是检索层的事，不在本次治理范围。

## 6. 顺带修的查看器（同一轮，2026-11-20）

用户反馈两条，都在整屏查看器上：

1. **图片跑出 DSH 窗口，看不到**。根因不是尺寸表算错，而是 flex 的几何：
   `.knit-lightbox` 用 `align-items:center`，stage 的交叉轴高度于是等于**内容高**，
   `img{max-height:100%}` 的百分比没有确定高度可依 ⇒ 大图按原始像素铺开，直接画到窗口外。
   修法：根容器 `align-items:stretch` + `overflow:hidden`、stage `height:100%`、图片宽高双向封顶。
2. **滚轮翻页太猛**。一次触控板惯性会触发几十个 `wheel` 事件，每个事件都换一张图 ⇒「滑一下飞好几张」。
   直接删掉滚轮翻页（画布与整屏都不再挂 `onWheel`），改成整屏显式的 `‹` `›` 按钮
   （`data-knit-lightbox-prev/next`）；方向键、左列缩略图、画布里的上一张/下一张照旧。

两条都有守卫：CSS 四条属性逐条断言；源码断言 `onWheel` 不许再出现在查看器上。
