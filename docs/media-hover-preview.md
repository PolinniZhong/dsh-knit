# 媒体档 · 悬停看大图 · 设计记录

> **状态：已实现、未发布**（客户端半边 ⇒ 只需硬刷新，不用重启 DSH）。
> 不随包发布（`docs/` 不在 `package.json` 的 `files` 白名单里）。
>
> 起因（用户原话）：「媒体模块，鼠标悬停在媒体文件的图片文件时，悬停浮窗预览功能可能实现吗？默认 800X800 px？」

## 一、边长上限 = **420**（原来是 800，用户看过之后改的）

> **2026-10-21 修订**：第一版上限按用户说的 800 做，在真机上试过之后他说「现在浮窗太大了」，
> 并在截图上用红框标出想要的大小 —— 约等于原来的**一半**。所以 `HOVER_SHOT_MAX` 从 800 改成 **420**。
> **这是一个人眼定的大小，不是算出来的**：要再调只改这一个数。

面板本身只有几百像素宽（实测 320–632px），硬开 800×800 会**盖住对话区**。所以：

```
盒子边长 = min(HOVER_SHOT_MAX, 卡片左侧/右侧可用空间, 视口 - 2×留白)
```

宽高各自再夹一次，图片在盒子里 `object-fit: contain` 等比铺满（不裁切、不放大到糊）。
所以：屏幕宽裕时它就是 420；面板窄或窗口小时它跟着收 —— **要的是「看得清」，不是「铺满」**。

## 二、摆在哪

- 默认摆在卡片**左侧**（面板在右边，浮窗往对话区那边让，不压住网格）；
- 左侧放不下就**翻到右侧**；
- 垂直以卡片中线居中，放不下就夹进视口（盒子比卡片高时，居中让位于「不出界」）；
- 拿不到卡片矩形（测试替身 / 事件不带 `currentTarget`）⇒ 视口居中，仍然守 800 上限。

整套几何是**纯函数** `hoverShotBox(card, view, opts)`：只吃两个矩形，不读 DOM —— 所以「上限 / 翻转 / 夹紧 / 窄屏收缩」
这四件事都能被真断言钉住。

## 三、交互取舍

| 决定 | 为什么 |
|---|---|
| **停 350ms 才出现** | 鼠标扫过网格时一路闪是最烦的；短了会闪、长了像没反应 |
| **离开即收** | 它只是「看一眼」，没有「保持」的必要 |
| **滚动就收** | 它是 `position:fixed`，不跟卡片走 —— 留着只会错位 |
| **只做图片** | 视频要解码 + 起播放器，代价与噪声都不是一个量级；视频仍走点击预览 |
| **`pointer-events:none`** | **它绝不许挡住卡片的点击与双击**（这条有 CSS 守卫） |
| **`z-index:60`、同一套外框** | 与入口那个悬停浮窗（`.knit-peek`）同一层级、同一套圆角/阴影/边框 —— 不新造一种浮层语言 |
| **`alt=""`** | 纯装饰：文件名已经在卡片上，重复念一遍是噪声 |

**成本明说**：`/api/raw` 与 `/api/attachment` 都带 `no-store`，所以**每次悬停都会重新取一次字节**（浏览器不缓存）。
350ms 的延迟已经把「鼠标扫过」挡掉了；真要彻底省，只能在服务端加缓存头 —— 那是另一条改动，没做。

**键盘可达性**：悬停不是唯一的看大图方式 —— 点开卡片仍然是就地预览（键盘 `↑↓` + `Enter` 也能到），
所以这个浮窗是**补充**，不是唯一入口（无障碍 P0 那条不破）。

## 四、取证

| 层面 | 手段 | 结果 |
|---|---|---|
| 几何（纯函数） | 2 条断言 | 全绿：≤ `HOVER_SHOT_MAX`、优先左侧、左边没地翻右侧、夹进视口、窄视口收缩、无矩形时居中 |
| 交互 | 5 条（延迟 / 提前离开 / 视频不弹 / 滚动收起 / 对话图走附件地址） | 全绿 |
| CSS | 1 条 | `position:fixed`、`pointer-events:none`、`z-index:60`、`object-fit:contain` |
| **守卫是否空转** | **6 条突变逐条证伪** | **6/6 如期变红**：视频也弹 / 立刻弹 / 不守 800 / 永不翻右侧 / 滚动不收 / 去掉 pointer-events |

⚠️ **真人真机验收还没做**：要在真面板上把鼠标停在几张图上看看 —— 大小、位置、延迟的手感只能人眼判断。

## 五、这一版踩到的坑

**CSS 注释里写了反引号**（`` `pointer-events:none` ``）⇒ 整个模板串被截断，`node --check` 报
`Unexpected identifier 'pointer'`。这是 L1 §6.1 明写着的坑（「注释里不能出现反引号」），我自己踩了一次。
代价很低（`node --check` 立刻红），但这正是那条军规存在的理由 —— 换成运行时才知道的那种写法，就是白屏。

## 六、媒体档的排序（2026-10-22 用户裁决，与悬停无关但同属媒体模块）

> 原话：「媒体这里不用跟随 Agent 读了它进行排序，目前就是以上传时间排序就可以，最新的放在前面就够了……
> 文档可以是调用，但是图片不需要有这种逻辑」。

- **媒体档一律按时间倒序**，不看相关性；文档 / 代码仍然保留「相关 / 最新」。
- **请求就是 `sort=time`**（不只改显示）：宿主因此不做无用的相关度计算，截断也按时间切。
- 网格里**自己再排一次**：工作区文件用 `mtimeMs`、对话里生成的图用事件时间，**同一条时间轴**合并后倒序；
  收藏仍然前移（稳定分区 ⇒ 两组内部都还是时间倒序）。
- 排序组在媒体档**禁用并如实显示「最新」在生效**（控件不消失、布局不跳、悬停有一句解释）；
  **偏好本身不动** —— 切回文档 / 代码还是你原来选的那个。
- 副作用（顺带正确的）：变更关联区只在相关序出现 ⇒ 媒体档里它自动不出现。

## 七、双击全屏查看器（2026-10-22，参照用户给的 Codex 截图）

用户要的三件事，逐条落地：

| 要求 | 实现 |
|---|---|
| **双击图片 → 全屏** | 双击图片卡片打开 `.knit-lightbox`（`position:fixed; inset:0`）；**视频不走这里**（仍开新标签页 —— 视频没有「全屏看一张图」这个语义） |
| **点图片以外 → 关闭** | 遮罩点击＝关；**图片本身** 与**左侧缩略图带**都 `stopPropagation`（否则想看清细节点一下就关了） |
| **左侧一列「近 10 张」** | `lightboxRail()` 取**当前这张附近**的 10 张（不是「最新 10 张」——双击第 30 张时最新 10 张里没有它，导航就断在画面外）。两端夹紧，当前那张高亮 |
| **图片以外是毛玻璃，且随主题变** | `--knit-scrim` 两套：浅色 `rgba(255,255,255,.62)` / 深色 `rgba(18,18,20,.72)`，配 `backdrop-filter: blur(22px) saturate(1.1)` |

**另外加的**（不然光看图就断手）：`←` `→` 在带子里前后翻、`Esc` 关；
`role="dialog"` + `aria-modal` + 打开即聚焦（键盘一进来就能用）。
**刻意没做**（用户没要，不顺手塞）：缩放百分比、下载、用其他应用打开。

⚠️ **层级与优先级**：查看器 `z-index:70`（在悬停浮窗与菜单的 60 之上）；
它的 `Esc / ← / →` **在根上的捕获阶段**先吃掉，不许漏到列表的键盘导航。

### 取证

| 层面 | 手段 | 结果 |
|---|---|---|
| 带子算法（纯函数） | 2 条 | 全绿：最多 10 张、含当前这张、两头夹紧、不足 10 张给全部、可注入上限 |
| 交互 | 5 条 | 全绿：双击开 / 点遮罩关 / 点图片不关（且真的 `stopPropagation`）/ 点缩略图换图且不关 / `Esc` 关 + `←→` 翻页 + 视频双击不进来 |
| 主题 + CSS | 1 条 | 两套 `--knit-scrim` **必须不同**（否则「随主题变化」是假话）、`backdrop-filter` 真的在、`z-index:70`、图 `contain` |
| **守卫是否空转** | **7 条突变逐条证伪** | **7/7 如期变红**，还原后逐字节一致 |

⚠️ **真人真机验收还没做**：毛玻璃的手感、遮罩深浅、缩略图带的位置与大小，都得人眼看。

### 这一版踩到的一个真问题

`lightboxStep()` 最初读的是**渲染时捕获的** `lightboxIndex`：连着按两下 → 第二下若还落在同一次渲染的闭包里，
它会拿**陈旧的下标**再算一遍，结果只前进一格（证伪时抓到）。改成**函数式更新**（从 `setLightboxRel(current => …)`
的当前 rel 推下一步）后就稳了 —— 顺带把 `lightboxIndex` 从依赖里去掉。

### 补记（同日第二次）：必须是**整屏**，不是面板那一块

用户第一次试完说：「不是双击后回到我们当前下方的一个显屏一栏，是**整个屏幕**」。

两个原因，**两个一起修**（只修一个都会漏）：

1. **`position:fixed` 被祖先的 transform 困住**。宿主的右侧栏是滑入的（有 `transform`），那一层成了
   containing block ⇒ `fixed` 变成「相对侧边栏」，于是只盖住面板。**CSS 逃不出来** ——
   改成 `ReactDOM.createPortal(node, document.body)`（`mountLightbox()`，取不到就降级就地渲染）。
2. **层级不够**。`z-index:70` 与悬停浮窗同一档，压不住宿主自己的侧栏与对话 ⇒ 提到**模态级**
   `2147483000`。

连带两处必须跟着改（否则 portal 之后会静默失效）：

- **遮罩变量挪到查看器自己身上**：`--knit-scrim` 原来定义在 `.knit-root`，portal 到 body 之后
  读不到那层变量 ⇒ `background` 整条作废、遮罩变透明。现在定义在 `.knit-lightbox` 上，
  深色用**全局选择器** `body[data-ds-dark-theme] .knit-lightbox` 覆盖（不依赖 `.knit-root`）。
- 缩略图「当前」描边用 `var(--knit-accent, <官方品牌令牌>)` 兜底。

守卫（形状级，因为测试替身没有 DOM）：渲染必须经过 `mountLightbox`、portal 目标是 `document.body`、
层级 ≥6 位、`--knit-scrim` **只许一处真源**。4 条突变逐条证伪，全部如期变红。

### 补记（同日第三次）：照 DSH 自带查看器的方向补齐

用户：「就按照 Deepseek 延伸对话中的图片，全屏一览的方向去实现」。

**查过宿主**（`app.asar` 是单个 148 MB 归档，不是目录 —— 上次 `cd` 进去 grep 空跑就是在这里出过假绿）：
里面有 `Lightbox`（47 处）、`image-preview`（29 处）、`closeButton`（38 处），但 `lightbox-` 前缀 0 处
（它用 Tailwind 那套），反编译压缩包性价比太低，**以截图里的可观察行为为准**。

对照之后只差一处：**右上角的 `✕`**。我原来只有「点图片以外」和 `Esc` ——
第一次用的人不知道该往哪点。已补：

- `h('button', { className: 'knit-lightbox-close', 'aria-label': …, title: '关闭（Esc）' }, '✕')`，
  绝对定位 `top:18px; right:18px`，悬停有反馈；
- 用**真 `<button>`** 而不是带类名的 `<span>` —— 后者看着一样，但键盘 Tab 不到、读屏也不当按钮。
  这条是**证伪时抓到的**：把 button 换成 span，原来只查类名的断言照样绿。

带子**仍在左边**（按用户第一次红框的要求）；DSH 那边在右边 —— 要换是一句话的事。

## 八、撤掉媒体档的「单击就地预览」（2026-10-22 用户裁决）

> 原话：「将媒体中心原来单击在我们下方悬屏预览这个交互删除掉，现在双击悬屏预览已经生效了。」

**撤掉的是什么**：媒体档里「单击卡片 → 下方弹出预览面板（黑底 + 预览头：全屏 / 收藏 / 本地打开 / ✕）」。
现在「看」这件事由两条路承担：**悬停看大图**（420px）与**双击全屏查看器**。

### 连带三件事（不处理就是静默丢功能）

1. **「收藏」「本地打开」原来只活在那个被撤掉的预览头里** ⇒ 搬进**全屏查看器**的工具条
   （✕ 左边）。⚠️ 对话里生成的图**不显示这两个按钮** —— 它还没有工作区路径，给了就是死按钮。
2. **视频不能进查看器**（查看器只做图片）⇒ 视频的**双击仍然就地预览**（播放器 / 收藏 / 本地打开都在那儿）。
   鼠标与键盘一致：`Enter` 在图片上进查看器、在视频上就地预览。
3. **单击与方向键只移光标**（`onSelect: () => setCursor(...)`，`↑↓` 不再 `openPreview`）——
   列表不再有任何「点一下就占掉半屏」的入口。

### 测试是**改写**不是删除

四条用例原本钉着「单击弹预览」，行为变了它们当然红（L0 §11 规则 6：
**不许删测试让 CI 变绿**，先判断是代码错还是断言错）。逐条改成新规格，并保住它们原本值钱的部分：

| 用例 | 改法 |
|---|---|
| 点图片就地预览 | 改成「单击只移光标、**不弹预览**、不请求 `/api/doc`；双击才进查看器」 |
| 点视频就地预览 | 改成「单击不弹；**双击**才弹」，播放器的 `controls/autoPlay/muted/playsInline` 断言原样保留 |
| 媒体档不出现查找条 | 前提从「单击图片」换成「双击视频」把预览打开，其余断言不动 |
| 媒体预览头有收藏 | 改成「**查看器**里有收藏」，落盘断言（按工作区根存、取消后不留空数组）原样保留 |

外加两条新的：`↑↓` / `Enter` 的分流（图片→查看器、视频→就地预览），以及「对话图没有收藏 / 本地打开」。
5 条突变逐条证伪，全部如期变红。

### 补记（同日第四次）：左列是**竖排**的，所以 ↑↓ 必须能翻

用户：「选中左边的那个图片…双击图片全屏，左边那个图片列表可以使用鼠标上下箭头进行切换移动。」

三件事：

- **`↑↓` 与 `←→` 等价**（`↑`/`←` 上一张、`↓`/`→` 下一张）。左列是竖的，`↑↓` 才顺手；`←→` 留着不冲突。
- **滚轮在图片区翻页**（`onWheel` 挂在 `.knit-lightbox-stage` 上，**不挂遮罩**）——
  左列自己会滚（`overflow-y:auto`），滚轮在它上面必须滚列表，不能被翻页抢走（有断言：左列**不许**有 `onWheel`）。
- **换图时把当前缩略图滚进可视区**（`scrollIntoView({ block: 'nearest' })`）：10 张在小屏上会溢出，
  `nearest` 保证「已经在视野里就一格不动」，不会抖。

⚠️ 这条守卫第一版**是空转的**：断言写的是 `scrollIntoView({ block: 'nearest' })` 这个串，
而它**在预览查找里早就有一处** ⇒ 把实现删掉照样绿。改成绑定 `active.scrollIntoView(...)` 之后才真的红。
这就是「守卫必须证伪一次」那条军规的又一个实例。
