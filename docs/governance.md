## 规则

1. **测试数量不是 KPI**：一条测试对应一个可证伪的行为；不为降低数字删测试。
   新功能优先加在已有测试文件的对应分组里，不再新建「什么都测一点」的巨型测试文件。
2. **新代码优先复用既有层**：列表行复用 `DocRow`、预览复用 `PreviewPanel`、图片/正文复用既有
   `/api/raw` / `/api/doc` / `PreviewPanel`；不要为一个小功能再造第二套渲染或第二条读取路径。
3. **客户端是「分片源码 + 生成单文件」**：源码在 `tools/client-src/`，由 `npm run build:client`
   拼成 `src/client/client.js`；不要手改生成物。新增功能必须：
   - 先找现有纯函数/组件扩展；
   - 把新增区块用清晰的 `/* ── vX.Y 功能名 ── */` 边界标出；
   - 单片超过 3 500 行先治理再加（见 `client-architecture.md`）。
4. **一次性交接文档去 L3**：`99_暂存文档/`（工作区层），不进 `knit/docs/`、不进包。
   设计记录留在 `knit/docs/`。
5. **未提交改动要能整块 review**：一个功能一个提交；发布前 `git diff --stat` 与测试数一起看，
   不把「测试多了」当成「功能好了」。
