### 🔴 录这条动图时发现的两件事（都写进了图注与工具里）

1. **重排不是瞬时的，正确说法是「0–5 秒」。** 面板是**每 5 秒轮询一次**（`POLL_MS`，
   见 `src/client/client.js`），所以重排在发消息之后的 0–5 秒内落到哪一帧全看运气。
   实测两次：一次 2.9 秒、一次 2.3 秒。
   ⚠️ **发布规划 §4.4 与旧图注里那句「让列表在 1 秒内重排」是不准的** —— 已改掉。
   动图按 10 fps 编码、比真实时间快（这是一般动图的惯例，但图注里要说明）。
2. **面板列表被滚动过就拍不出重点**：重排看的就是「顶上那几篇换了没有」，
   如果列表停在半截，画面上看不出变化。录之前把 `scrollTop` 归零。

### 这条动图是怎么来的（**真实 GUI，不是原型**）

执行环境原本**没有任何截屏能力**（`screencapture` 看不到显示器、AppleScript 发不出 Apple Event、
Playwright 自带 Chromium 起不来、`avfoundation` 列不出视频设备 —— 四条路都堵，记录在
`03_发布/发布文档规划.md` §4.4）。但 2026-09-21 发现第四条之外还有一条：
**`chrome-headless-shell` 用原始命令行直接起、不要走 Playwright 的 launch API** ——
它能加载真实的 DSH GUI（日志里能看到 `[knit] registered on the official right sidebar`），
再通过 CDP 的 `Page.captureScreenshot` 逐帧抓。画面的每一处都是真宿主、真插件、真排序，
**不是 HTML 原型**。

编码那半段已自动化：`node tools/make-demo-gif.mjs --in <帧目录> --crop 560,0,2240,1520 --width 1100`
（`--crop` 是这次加的：真机录屏是整屏，README 只想要「对话 + 右侧栏」）。

⚠️ **录这两句问法会真的开一个会话并跑两个回合**（跑完立刻停止）。这次留下的是一个

### npm 上这张图从来没显示过（从 `0.5.0` 起）

三个事实叠在一起：

1. 两份 README 原来用的是**相对路径** `docs/screenshot.png`
2. 而 `docs/` **不在 `package.json` 的 `files` 白名单**里 → 文件根本没进 tarball
   （实测 `0.12.0` 的包里没有 `docs/`；`unpkg.com/dsh-knit@0.12.0/docs/screenshot.png` → **404**）
3. npm 的 README 渲染不会把相对路径重写成包内地址

所以 npm 页面上一直是个**坏图**，只是没人注意到 —— 会看的人是少数，且大多从 GitHub 过来。

### 已经改成绝对 raw URL（2026-09-19，未发布）

两份 README 的图片地址改成：

```
https://raw.githubusercontent.com/PolinniZhong/dsh-knit/main/docs/screenshot.png
```

**为什么不干脆把 `docs` 加进 `files`**：那会让每个装包的人都下走 380 KB 只为了看 README 里的图。
绝对 URL 由 GitHub 托管、不占包体，而且**以后换图不用再发版本**。
