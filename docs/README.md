## 这一张暴露的三处硬编码中文 —— ✅ 已修（2026-09-19，未发布）

🔴 **图里混了中英两种语言**：面板是**英文**（`Relevant` / `Docs` / `Fullscreen` /
`Open locally` / `Referenced by …`），但文档行右边的相对时间显示的是**中文** `3 分钟前`。

原因是那三处文案硬编码在客户端里，没进 `ZH` / `EN` 词典。扫过整个客户端后确认：
**词典之外只有这三处裸中文**，其余文案全部走 `t()`（所以它们是例外，不是惯例）：

| 位置 | 原样 | 影响面 | 现在 |
|---|---|---|---|
| `relTime()` | `刚刚` / `X分钟前` / `X小时前` / `昨天` / `X天前` / `X月X日` | **英文界面下用户直接看见**（就是这张图） | 六个键 `time.*`，走 `t()` |
| 文档列表的 `aria-label` | `最近文档` | 读屏用户 | 键 `list.aria` |
| better-sidebar 的 tab 标题 | `Knit 最近文档` | 装了这个宿主时可见 | 复用 `guide.title`（与官方 tab 同一个键，顺带把两个宿主的口径统一了） |

违反 `AGENTS.md` §4.5。**已按 §4.5 的流程修掉：中英两边的键同时加，值走 `t()`。**

### 加了 4 条守卫（`test/i18n.test.mjs`），并且**验证过它们在旧代码上会红**

| 守卫 | 抓什么 |
|---|---|
| 英文环境渲染出的整棵树里一个汉字都没有 | 任何**渲染出来**的硬编码中文 |
| 英文环境下 `aria-label` / `title` / `placeholder` / `alt` 里没有汉字 | 属性里漏掉的（渲染文本守卫看不见这类） |
| 相对时间的六个分支都随语言 | 逐个粒度核对中英两套写法 |
| better-sidebar 的 tab 标题随语言 | 注册层面的标题 |

既有那条冒烟用例（`assert.ok(!/刷新|按/.test(enText))`）**当时没抓住 `3 分钟前`** ——
因为它只写死了两个词去查。新守卫改成「不许有任何汉字」，不再靠枚举词。

> ### ⚠️ 一条比修 bug 更值钱的教训：**守卫必须真的跑到那条分支**
>
> 守卫的第一版用的是现成的 `listPayload()`（两篇文档）。我把 `分钟前` 硬编码**改回去**做证伪时，
> **守卫竟然全绿** —— 因为那两篇文档只落在 `justNow` 与 `yesterday` 两个分支上，
> 补丁那条分支**根本没渲染出来**。而这恰恰就是真机截图里漏出来的那一条。
>
> 修法：新增 `timePayload()`，**六个时间粒度各来一篇**，守卫必须看见全部六条。
> 再证伪时 4 条全红（外加 1 条既有用例，因为我那一刀误替换了两处）。
>
> **「测试通过」不等于「测到了」—— 没跑到那条分支的守卫是一盏空转的绿灯。**

### npm 上这张图从来没显示过（从 `0.5.0` 起）

三个事实叠在一起：

1. 两份 README 原来用的是**相对路径** `docs/screenshot.png`
2. 而 `docs/` **不在 `package.json` 的 `files` 白名单**里 → 文件根本没进 tarball
   （实测 `0.12.0` 的包里没有 `docs/`；`unpkg.com/dsh-knit@0.12.0/docs/screenshot.png` → **404**）
3. npm 的 README 渲染不会把相对路径重写成包内地址

所以 npm 页面上一直是个**坏图**，只是没人注意到 —— 会看的人是少数，且大多从 GitHub 过来。

### 已经改成绝对 raw URL（2026-09-19，未发布）

两份 README 的图片地址改成：

```
https://raw.githubusercontent.com/PolinniZhong/dsh-knit/main/docs/screenshot.png
```
